# Log Collector

## Утилита командной строки для агрегации и анализа логов из распределённых источников. Позволяет собрать логи множества экземпляров сервиса в единый структурированный файл с фильтрацией по времени и уровню критичности.

## Основные возможности

* **Агрегация логов** из множества экземпляров сервиса в один файл
* **Фильтрация по времени**:
    * Абсолютное время (--date 2026-02-09 --time 09:00:00)
    * Относительное время (--time "10 min ago", --time "9 hours")
    * Комбинированный формат (--datetime 2026-02-09_09:00:00)
* **Фильтрация по уровню**:
    * all — все логи
    * warning — предупреждения и ошибки
    * error — только ошибки
* **Автоматическое дробление** выходного файла при превышении заданного размера (--mlength 500)
* **Корректная обработка многострочных записей** (трейсбеки, стек-трейсы)
* **Поддержка ротированных логов** (автоматическое обнаружение и сортировка по времени)
* **Человекочитаемый формат вывода** с разделителями между экземплярами

## Примеры использования

```bash
# Собрать все ошибки с 9 утра 7 февраля 2026
collect_log --date 2026-02-07 --time 09:00:00 --level error \
  --input /opt/service/logs \
  --output /tmp/errors_2026-02-07.txt

# Собрать предупреждения и ошибки за последние 15 минут
collect_log --date 2026-02-09 --time "15 min ago" --level warning \
  --input ./logs \
  --output ./recent_warnings.txt

# Собрать все логи с конкретного момента (с дроблением файла на части по 500 МБ)
collect_log --datetime 2026-02-09_09:00:00 --level all \
  --input /var/log/my_service \
  --output /backup/logs_full.txt \
  --mlength 500

# Использование сокращённых параметров
collect_log -d 2026-02-09 -t 10 -l ER -i ./test_logs -o errors.txt
```

## Параметры командной строки

* `--date` <=> `-d` - Обязательный* - Дата в формате `ГГГГ-ММ-ДД` - (пример) `2026-02-09`
* `--time` <=> `-t` - Не обязательный - Время или относительное выражение - (пример) `09:00:00`, `9`, `10 min ago`, `1 hours ago`, `9 hours`
* `--datetime` <=> `-dt` - Обязательный* - Комбинированный формат `ГГГГ-ММ-ДД_ЧЧ:ММ:СС` - (пример) `2026-02-09_09:00:00`
* `--level` <=> `-l` - Обязательный - Уровень логов - (пример) `all`/`A`, `warning`/`WE`, `error`/`ER`
* `--input` <=> `-i` - Не обязательный - Директория с логами - (пример) `/opt/service/logs`, (по умолчанию `.`)
* `--output` <=> `-o` - Обязательный - Выходной файл - (пример) `/tmp/errors.txt`
* `--mlength` <=> --- - Не обязательный - Макс.размер файл в МБ - (пример) `500`

> *- обязательно должен быть указан либо `--datetime`, либо `--date` (с опциональным `--time`)

### Форматы времени

* Часы  - (пример) `9` - `09:00:00` текущего дня
* Часы:минуты - (пример) `9:30` - `09:30:00` текущего дня
* Полный формат - (пример) `09:30:45` - `09:30:45` текущего дня
* Относительное - (пример) `10 min ago` - Текущее время минус 10 минут
* Относительное - (пример) `9 hours` - `09:00:00` текущего дня

## Формат вывода

Результат сохраняется в структурированном виде с разделителями:

```text
===================================   100   =================================================
2026-02-09 09:23:04,623 - ERROR - [Model_updated] Ошибка в ModelInstance.Process: [Errno 2] No such file or directory: ''
Traceback (most recent call last):
  File "/opt/service/core/model.py", line 145, in process
    with open(filepath, 'r') as f:
FileNotFoundError: [Errno 2] No such file or directory: ''

2026-02-09 09:56:26,837 - ERROR - [Model_updated] Ошибка в ModelInstance.Process: [Errno 2] No such file or directory: ''
Traceback (most recent call last):
  ...
===================================   100 (END)   =================================================


===================================   NEXT   =================================================


===================================   101   =================================================
2026-02-09 10:15:22,104 - ERROR - [DB_Connection] Таймаут подключения к базе данных
...
===================================   101 (END)   =================================================
```

> ### Особенности формата:
> * Каждый экземпляр отделён разделителями с указанием ID
> * Многострочные записи (трейсбеки) сохраняются как единое целое
> * Между экземплярами добавляется маркер `NEXT` для удобства навигации
> * При использовании `--mlength` каждый файл содержит целые экземпляры (никакой экземпляр не разбивается между файлами)

## Продвинутые сценарии

### Сбор ошибок после инцидента

```bash
# После падения сервиса в 14:23 собрать все ошибки с этого момента
collect_log --datetime 2026-02-09_14:23:00 --level error \
  --input /var/log/payment_service \
  --output /incident/investigation_errors.txt
```

### Ежедневный отчёт об ошибках

```bash
#!/bin/bash
# daily_error_report.sh
DATE=$(date +%Y-%m-%d)
collect_log --date "$DATE" --time 00:00:00 --level error \
  --input /opt/app/logs \
  --output "/reports/errors_${DATE}.txt"
```

### Мониторинг в реальном времени (с комбинацией с другими утилитами)

```bash
# Собрать ошибки за последние 5 минут и показать последние 20 записей
collect_log --date $(date +%Y-%m-%d) --time "5 min ago" --level error \
  --input ./logs --output /tmp/latest_errors.txt && \
tail -20 /tmp/latest_errors.txt
```

## Ограничения и особенности

* Формат временных меток - Поддерживается только формат `2026-02-09 09:23:04,623` (дата + время + миллисекунды)
* Кодировка файлов - Ожидается UTF-8. Файлы с другой кодировкой пропускаются с предупреждением
* Дробление файлов - При указании `--mlength` экземпляры не разбиваются — целостность сохраняется
* Производительность - Обработка 1 ГБ логов занимает ~15-30 секунд на современном CPU
* Память - Потоковая обработка — объём памяти не зависит от размера логов
